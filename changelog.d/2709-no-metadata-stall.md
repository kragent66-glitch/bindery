### Fixed
- **A magnet that never gets its metadata is now failed instead of sitting at downloading for ever** (#2709): a torrent your client accepted but never resolved has no files, no size and no progress, and no client calls that an error, so nothing ever cleaned it up. Once it is older than the stall timeout (2 hours by default) Bindery removes it from the client, fails the queue row saying the metadata never resolved, and searches again, skipping that release so the search can pick another one. Works with Transmission, qBittorrent, Deluge and rTorrent, and Transmission audiobook downloads are now checked for stalls too. The release is not blocklisted, because a magnet with no metadata usually says more about the connection than the release, and if most of a client's unfinished torrents look that way Bindery logs a warning and leaves them all alone. Thanks ccarpinteri for the report.
