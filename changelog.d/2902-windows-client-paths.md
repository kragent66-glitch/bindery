### Fixed
- **Torrent imports work on the Windows binary when the download client runs in Docker** (#2902): Bindery joined the client's save path and file names with Windows backslashes before applying the path remap, so a qBittorrent path such as `/downloads/.Completed/Book/Vol 17.epub` became `\downloads\.Completed\...`, a remap like `/downloads:H:\Downloads` never matched, and every import failed with "no book files found" although the file was there and Manual Import worked. Paths are now joined the way the client writes them and only turned into a Windows path after the remap, for qBittorrent (including the rdt-client content path fallback), Transmission, Deluge and rTorrent. On Windows the qBittorrent health check now suggests a remap in the client's own form and compares folders without regard to letter case, and the Windows binary no longer defaults `BINDERY_DOWNLOAD_DIR` to `/downloads`, a folder on whatever drive Bindery started from: unset, the health check only asks that the client's folder exists. File names from a download client that climb out of the torrent folder with `..\` are now refused on every platform. The deployment guide explains how to set environment variables on Windows and how to remap a Docker client's paths, and the Storage settings hint no longer mentions a config file that does not exist. Thanks fearvector on Discord for the report.
